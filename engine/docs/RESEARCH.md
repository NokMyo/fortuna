# ORACLE Engine 1.1.0 — 정밀 연구 분석

이 문서는 **실제로 실행되는 확장 기능**의 계산 계약입니다. 앱은 1.3.0이며 모든 실행 로직은 `engine/src/`의 x64 어셈블리입니다. 일반 분석의 기존 정책과 연구용 공동 확률모형을 구분합니다. 실제 로또에서 예측 우위가 입증되었다고 주장하지 않습니다.

## 실행과 결과

앱의 **분석 → 정밀 연구 분석** 또는 아래 명령으로 여섯 확장 기능을 실행합니다.

```bat
build\FebiusFortuna.exe --research history.csv report.txt
```

**전체 조합 정밀 연구 (장시간)** / `--research-full`은 빠른 점수로 조합을 선별하지 않고 모든 조합에 깊은 점수를 적용합니다. 전체 재검증에서도 이를 반복하므로 매우 오래 걸릴 수 있습니다. 분석은 기존 작업 스레드에서 실행하며 취소할 수 있습니다. 실패·취소한 연구 결과는 사용 가능한 상태로 표시하지 않습니다.

연구에는 기존 모델 12개를 제외한 12회 실행과 전체 모델 기준 실행 1회, 각 실행의 모든 시간순 학습/확인 회차, 공동 모형의 내부 설정 선택과 외부 평가, 확률분포 전체 합산, 반복 불확실성 분석이 포함됩니다. 처리 시간은 데이터 길이와 컴퓨터에 크게 좌우됩니다. 작은 60행 가상 입력도 수십 초 이상의 계산이 필요할 수 있습니다.

완료 후 **분석 상세**에 연구 결과가 추가됩니다. **공동 모형 번호 생성 (연구용)**은 아래의 공동 예측분포 Q에서 번호를 뽑습니다. 기존 번호 생성 버튼은 기존 검증 정책을 사용합니다. 연구용 생성의 기존 ORACLE 지수는 여전히 기존 코어의 상대 점수이며 공동 모형의 당첨확률을 나타내지 않습니다.

## 1. 여섯 번호 공동 확률모형

가능한 집합 S는 1..45의 서로 다른 여섯 번호입니다.

\[
 E(S)=\sum_{i\in S} a_i+\sum_{i<j\in S}b_{ij}+\sum_{i<j<k\in S}c_{ijk},\qquad
 P(S)=\frac{\exp E(S)}{Z},\quad Z=\sum_{|T|=6}\exp E(T).
\]

`JointEnumerate`는 Gosper 순회로 8,145,060개 조합을 정확히 한 번씩 평가합니다. 확률 합을 표본으로 근사하지 않습니다. 동일 순회에서 번호·쌍·삼중 관계의 모형상 포함 확률도 계산합니다. 번호별 포함 확률의 합은 6이어야 합니다. 이 '정확한 합산'은 알고리즘상 전수 합산을 뜻하며, 실제 구현에는 binary64 반올림 오차가 있습니다.

실제 연구용 예측·추출 분포는 다음과 같습니다.

\[
 Q(S)=\tfrac12/\binom{45}{6}+\tfrac12 P(S).
\]

계수 상한은 번호 0.05, 쌍 0.02, 삼중 관계 0.01입니다. 따라서 |E(S)|≤0.8이며 지수 계산은 안정적인 범위 안에 있습니다. `JointSample`은 균등 제안과 exp(E−0.8) 수락확률을 사용하는 거절 추출로 Q를 표본화합니다. 운영체제 난수가 실패하거나 수락 시도 8,192회가 소진되면 오류를 반환하고 다른 분포로 몰래 전환하지 않습니다. API로 여러 연구 게임을 요청하면 독립적으로 뽑으므로 동일 조합이 반복될 수 있습니다.

## 2. 하위 관계를 설명한 뒤 상위 관계 축소

번호 → 쌍 → 삼중 관계의 순서로 계수를 만듭니다. 각 단계는 바로 앞 단계의 **정규화된 모형**에서 기대 포함 확률 p_f를 얻습니다. 관측 횟수 c_f와 학습 회차 N에 대해

\[
 v_f=\frac1{Np_f(1-p_f)+1},\qquad z_f=(c_f-Np_f)\sqrt{v_f}
\]

를 계산합니다. 단계에 포함된 유효 특징 수를 M이라고 할 때

\[
 \tau^2=\max(\operatorname{mean}(z_f^2)-1,0),\quad
 w=\frac{\tau^2}{\tau^2+\lambda},\quad
 \theta_f=\operatorname{sign}(z_f)\min\{cap,\;w\sqrt{v_f}(|z_f|-\sqrt{2\log M})_+\}.
\]

이것은 **정규 근사 관측모형의 경험적 베이지안 단계별 축소에 희소화 문턱을 결합한 구현**입니다. 완전한 다항분포의 베이지안 사후분포, MCMC, 정확한 특징별 FDR 보장을 구현했다고 주장하지 않습니다. 특징 간 상관 때문에 가족 크기 문턱만으로 엄밀한 다중검정 보장을 얻는 것도 아닙니다. 각 단계의 가중치와 계수 상한, 다음 회차 평가를 함께 사용합니다.

쌍의 잔차는 번호 모형의 기대값을 뺀 것이고, 삼중 관계의 잔차는 번호+쌍 모형의 기대값을 뺀 것입니다. 따라서 단순 빈도 중복보다 정교한 구조이지만 모든 매개변수를 공동으로 최적화하는 최대우도 해는 아닙니다. 추가 사후분포 추정이나 반복 최적화는 별도의 연구 과제입니다.

## 3. 후보 누락 검사와 확장

일반 정밀 연구에서는 빠른 점수 상위 4,096개를 깊게 평가해 512개를 선택합니다. 빠른 선별에서 탈락한 조합 중 서로 다른 512개를 균등 추출해 깊은 점수로 평가합니다. 현재 512번째 점수를 넘는 조합을 발견하면 빠른 후보를 8,192개로 늘려 **전체 선별과 깊은 평가를 다시 실행**합니다. 이후 새로운 감사 표본으로 남은 누락을 측정합니다.

점수 동률인 경우 실제 후보 목록을 확인하므로 모든 빠른 점수가 같아도 표본 추출이 멈추지 않습니다. 각 표본 단계의 시도 상한은 65,536회이며 실제 완료 표본 수를 보고합니다. 시드는 학습 접두 구간의 해시만 사용하고 본 분석의 난수 상태를 복원합니다.

보고서의 누락 수는 표본 진단입니다. 누락 0이 전체 공간에서 누락이 없다는 보장은 아닙니다. 전체 정밀 모드에서만 모든 조합에 현재 깊은 점수 함수를 적용하며, 그 함수가 실제 예측력을 가진다는 뜻은 아닙니다. 이 감사는 학습/확인/최종 필드에서 모두 동일하게 수행됩니다.

## 4. 완전한 모델 제거 재검증

`AnalyzeResearch`는 각 기존 성분 0..11을 제외하고 `AnalyzeOracle` 전체를 다시 실행합니다. 마지막 13번째 실행은 모든 성분을 사용하는 기준입니다. 제거된 성분은 깊은 점수, 적용 가능한 빠른 점수, 기준 표본 벡터/상관관계, 가중치 승격에서 제외합니다. 다른 성분이 사용하는 공통 원시 통계는 유지합니다. 이는 **점수 성분의 기여도 검사**이며 공통 특징의 모든 간접 효과를 제거하는 인과 분석이 아닙니다.

각 실행은 시간순 통계·정규화·선별·이웃 분석·가상 이력·학습 가중치·최종 30회 확인·표본 생성을 다시 수행합니다. 동일한 결정론적 프로토콜을 사용합니다. 결과는 학습 회차, 적중 평균, Brier, 학습/확인 로그 손실 합, 최종 균등 혼합, 확인 통과 여부입니다. 모델 11은 기존 비보정 군중 선택 휴리스틱이며 예측 성분으로 승격하지 않습니다.

비교 결과를 보고 좋은 모델 조합을 사후에 고른 경우 같은 결과를 독립 검증으로 다시 인용하면 안 됩니다. 이 구현은 제거 결과를 자동으로 새 모델 선택에 사용하지 않습니다. 모든 모델 부분집합을 탐색하거나 실제 데이터에서 발견 우위의 유의확률을 새로 주장하지 않습니다.

## 5. 중첩 시간순 평가와 사전 예측 기록

### 내부/외부 평가

공동 모형은 가장 최근 **최대 30개 외부 회차**를 평가하되 각 외부 시점 앞에 적어도 64행이 있어야 합니다. 외부 시점 t의 직전 네 회차는 내부 설정 평가에 사용합니다. t−4행까지만 학습한 각 λ∈{0.5,1,2} 모형을 그 네 회차의 로그 손실로 비교하고, 선택한 설정을 t행으로 재학습한 후 실제 다음 한 회차를 평가합니다. 설정 동률은 정해진 순서로 처리합니다. 60..63행의 최종 모형은 설정을 선택하지 않고 λ=1을 사용합니다.

번호별 Brier와 조합 전체 로그 손실 −log Q(S)를 기록합니다. 기존 고정 도전자(rho=0)의 로그 손실은 별도로 최소 50% 균등을 섞은 분포로 계산합니다. 따라서 기존 순수 도전자의 Brier와 동일한 분포에 대한 지표라고 오해하면 안 됩니다. 연구 모형은 희귀한 조합에도 양의 확률을 배정합니다.

과거 외부 평가의 누적 log-e = Σ log[Q_t(S_t)·8,145,060]도 보여주지만, 이를 보고 개발을 반복했다면 사전 예측의 증거로 사용할 수 없습니다. 최대 30개라는 계산 한계와 작은 평가 표본도 보고서에 표시합니다. 이 값으로 기존 운영 정책을 자동 승격하지 않습니다.

### 미래 회차 기록

**다음 회차 확률분포 기록**은 `%APPDATA%\Febius\Fortuna\oracle-forecasts.fjp`에 다음 내용을 추가합니다.

- 대상 회차, 학습 행 수, 로컬 저장 시각
- Z와 모든 공동 모형 계수: 다음 번호를 보기 전의 분포 전체
- 학습 데이터·설정 해시, 이전 기록 해시, 현재 기록 SHA-256
- 앞선 예측 평가 건수와 누적 증거 기록

아직 결과가 없는 같은 회차는 기존 기록을 재사용하고 덮어쓰지 않습니다. 다음 회차까지 포함한 CSV를 불러온 후 **사전 예측 기록 검증**을 실행하면 저장된 계수로 그 회차를 평가합니다. 매번 파일 처음부터 다시 계산하므로 같은 결과를 중복 가산하지 않습니다. 과거 학습 접두 구간이 바뀌었거나 회차·파일 길이·해시가 틀리면 거부합니다. 중간 기록을 건너뛰지 않습니다.

공정·독립 추첨이라는 귀무가설 아래, 각 회차 전에 결정된 정규화된 Q_t를 사용하면 E_n=∏[Q_t(S_t)·8,145,060]은 평균 1의 비음수 마팅게일입니다. 단일 사전 지정 기록에서 max log E≥log(20)을 사용하는 5% 경계는 반복 확인을 허용합니다. 여러 기록을 만든 뒤 가장 좋은 것만 고르는 경우까지 보정하지 않습니다. 누적 log-e는 실제 당첨확률이나 수익 보장이 아닙니다.

**로컬 시각과 해시는 외부 공증이 아닙니다.** 전체 파일을 다시 작성하거나 시계를 조작한 일을 독립적으로 증명할 수 없습니다. 공식 원천 인증도 없습니다. 예측 전 기록의 신뢰할 수 있는 외부 사본을 별도로 보존해야 합니다. 파일은 추가 기록 후 flush하며, 전원 손실로 잘린 파일에는 새 기록을 이어 붙이지 않습니다. 자동 복구·외부 타임스탬프 서비스는 포함하지 않습니다.

FJP1은 기록당 130,256바이트입니다. 앞의 144바이트는 헤더, 이후 16,260개 binary64 슬롯은 계수, 마지막 32바이트는 앞부분 SHA-256입니다. 쌍의 비사용/대칭 슬롯은 0입니다. 이전 기록 해시는 헤더 오프셋 96에 들어갑니다. 버전 1 파일에서 이 레이아웃을 바꾸지 않습니다.

## 6. 적응적 불확실성 계산

최종 데이터에서 학습 창(전체/앞 10% 제거/앞 20% 제거), 축소 설정(0.5/1/2), 관계 차수(1/2/3)를 바꾸고 매번 모형을 다시 맞춰 **전체 공간의 포함 확률**을 계산합니다. 처음 여섯 실험에서는 각 차수를 두 번씩 포함하고 이후에는 무작위 선택합니다. 원래 모형은 끝에 복구합니다.

최소 8회, 최대 32회, 4회 단위로 검사합니다. 각 번호 포함 확률의 실험 간 표준편차/√횟수 중 최댓값이 0.0005 이하이고 각 차수가 두 번 이상 관측되면 멈춥니다. 이것은 **추정된 Monte Carlo 표준오차 기준**입니다. 적응적 중단과 초기 차수 할당을 고려한 엄밀한 신뢰구간이라고 표현하지 않습니다. 상한에서 목표를 못 채우면 목표 미달로 기록합니다.

출력은 결합된 설정/데이터 섭동 분산, 차수별 평균 예측의 차이, 모형 내부 Bernoulli 분산의 번호별 평균, 추정 Monte Carlo 오차, 후보 누락 감사입니다. 서로 독립적으로 더할 수 있는 완전한 오차 분해는 아닙니다. 모든 현실의 불확실성이나 정확한 베이지안 신뢰구간을 포함하지 않습니다.

## 검증

`tests/research.py`는 작은 공간의 독립 NumPy 합산과 어셈블리의 확률·포함 확률·Z를 대조합니다. 균형 자료에서 균등 모형으로 축소되는지, 계수 상한, 학습 접두 구간 불변성, 내부 선택의 미래 차단, 누적 log-e 재계산, 취소, 실제 45C6 순회, 13회 전체 분석을 검사합니다.

`tests/research-windows.py`는 실제 Windows DLL의 호출 규격, 연구 생성, 사전 예측 기록 재사용, 평가 중복 방지, 저장된 분포에 대한 로그 증거, 과거 자료 변경과 기록 손상 거부를 검사합니다. 앱 검사에서는 DLL 없는 EXE의 `--research` 명령도 실행합니다. 가상 데이터에 대한 공학 검증이며 실제 로또 예측 우위의 실험 결과가 아닙니다.
