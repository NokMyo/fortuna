# 세 가지 추첨 방식

앱 1.4.0 · Fortuna ORACLE Engine 1.2.0 · ABI 1.0

먼저 1게임·5게임·10게임을 선택한 다음 추첨 방식을 누릅니다.

| 버튼 | 동작 | 데이터와 시간 |
|---|---|---|
| 예상 번호 추첨 | Windows 보안 난수로 모든 조합을 균등하게 추첨 | CSV 불필요, 즉시 실행 |
| ORACLE기반 예상 번호 추첨 | 일반 분석·전수 탐색·순차 검증 후 표준 정책으로 추첨 | CSV 60회차 이상, 첫 분석 후 결과 재사용 |
| ORACLE기반 심층 분석 추첨 | 공동 확률 모형·중첩 검증·편향 및 불확실성 연구 후 공동 모형과 균등 분포의 50:50 혼합으로 추첨 | CSV 60회차 이상, 일반보다 긴 첫 분석 후 결과 재사용 |

일반 모형의 검증 근거가 부족하면 균등 추첨으로 전환하며 화면에 표시합니다. 심층 모형은 예측 우위가 검증되지 않은 연구 결과입니다. 복잡한 분석이나 내부 점수를 실제 당첨 확률로 표시하지 않습니다. 공정하고 독립적인 추첨에서는 각 조합의 1등 확률이 같습니다.

랜덤 추첨은 저장된 분석 모형을 변경하지 않습니다. 마지막으로 완료된 동일 방식의 분석은 재사용하며, 다른 분석 방식으로 바꾸거나 새 CSV를 불러오면 필요한 분석을 다시 수행합니다. 분석 중에는 진행 상태와 취소 버튼이 제공됩니다. 실패나 취소를 다른 추첨 방식의 성공으로 표시하지 않습니다.

분석 메뉴의 전체 조합 정밀 연구는 심층 분석의 추가 정밀 옵션입니다. 사전 예측 분포 기록·검증과 분석 보고서도 계속 사용할 수 있습니다. 독립적인 랜덤/심층 게임은 같은 조합이 반복될 수 있습니다.

CSV를 열면서 프로그램을 시작하려면:

```text
FebiusFortuna.exe --open "당첨번호.csv"
```

## 어셈블리 규칙

`src/`의 앱 실행 로직과 `engine/src/`의 엔진 실행 로직은 x64 어셈블리로 작성합니다. 엔진 소스는 같은 저장소의 `engine/` 폴더에 분리하며 앱에는 정적으로 포함합니다. 배포된 EXE는 Windows 시스템 DLL을 사용하고 별도의 엔진 DLL, Python 또는 C 런타임을 요구하지 않습니다.

리소스 선언(`.rc`, `.manifest`), 빌드·패키징·테스트 스크립트(Python, PowerShell, shell), 외부 개발자용 API 선언 헤더는 개발 보조 파일이며 앱 실행 로직이 아닙니다. 새로운 런타임 기능을 다른 언어로 작성하지 않습니다. 어셈블리 자체가 최상의 속도를 보장하지 않으므로 실행 시간·정확성·메모리 사용을 함께 검증하고 분석 결과를 재사용합니다.
