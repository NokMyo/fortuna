# 기본 내장 추첨 이력

Febius Fortuna 1.9.1은 실행 파일에 로또 6/45 **1회차부터 1242회차까지 1,242개 추첨 이력**을 정적으로 포함합니다. GUI로 실행하면 계정·라이선스 확인 뒤 이 이력을 기존 엔진의 transactional CSV parser로 자동 로드하며, 따라서 별도 CSV를 선택하지 않아도 일반/심층 ORACLE 분석을 시작할 수 있습니다.

## 원본과 변환

이번 내장 데이터는 개발자가 제공한 `lotto.xlsx`의 `Lotto` 시트에서 가져왔습니다. 원본 시트의 열은 회차, 번호1~번호6, 보너스, 1·2등 당첨금/당첨수로 구성되어 있습니다. 현재 ORACLE 입력 계약에서 사용하는 **회차 + 본번호 6개 + 보너스**만 내장 분석 데이터로 변환합니다. 당첨금과 당첨자 수 열은 현재 엔진이 사용하지 않으므로 실행 파일에 넣지 않습니다.

변환 전에 1~1242 회차가 정확히 한 번씩 존재하는지, 여섯 번호가 1~45 범위에서 중복 없이 오름차순인지, 보너스가 1~45이며 본번호와 겹치지 않는지를 검사했습니다.

원본에서 변환한 canonical CSV payload의 SHA-256:

`10fe08fa5f52528e9fe2724662c1a859abbdd9ad42d1b36eac7d46a3e3d1f36b`

이 해시는 **동일한 내장 데이터인지 확인하기 위한 무결성 값**이지, 데이터가 공식 기관 자료와 일치함을 외부에서 인증하는 값은 아닙니다. 이번 작업에서는 원본 워크북의 구조와 값 범위를 검증했으며 별도의 공식 웹 데이터와 전 회차를 대조하지 않았습니다.

## 빌드와 런타임

저장소에는 변환 결과를 `resources/lotto-history.csv.gz`로 보관합니다. `scripts/generate-embedded-history.py`가 빌드 전에 gzip을 풀고 SHA-256과 1,242개 행 전체를 다시 검증한 뒤 임시 assembly include를 생성합니다.

최종 `FebiusFortuna.exe`에는 검증된 CSV 바이트가 정적으로 포함됩니다. Python, gzip 라이브러리 또는 Excel 파서는 실행 파일에 포함되지 않으며 런타임 실행 로직은 기존과 동일하게 x86-64 Assembly입니다.

`--self-test`도 내장 이력을 실제 엔진에 로드해 history count=1242, last round=1242인지 검사합니다.

## 외부 데이터

GUI의 **외부 CSV** 버튼은 기존 기능을 유지합니다. 사용자가 외부 CSV를 선택하면 그 실행 세션에서는 내장 이력 대신 선택한 데이터셋으로 교체됩니다. `--open`, `--analyze`, `--research`, `--research-full`의 명시적 외부 CSV도 그대로 우선합니다.

내장 데이터는 자동으로 인터넷에서 갱신되지 않습니다. 새 회차를 기본 탑재하려면 다음 앱 릴리스의 내장 데이터 소스를 갱신해야 합니다.
