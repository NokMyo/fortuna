# Fortuna ORACLE — engineering specification

ORACLE is an **analytical random generator**, not a claim that a fair lottery can be predicted. In a fair 6/45 drawing every one of the 8,145,060 combinations has the same jackpot probability. ORACLE deliberately separates *internal analytical preference* from *real-world probability*.

## Current ASM engine (0.1)

The executable is written in x86-64 assembly and does not use the C/C++ runtime. The Windows API is used directly for the GUI, file I/O, threading and cryptographic random bytes.

The pipeline is:

1. Parse and validate historical CSV rows.
2. Build number frequencies, three exponentially weighted time scales, last-seen gaps, a 45×45 pair co-occurrence matrix, structural histograms, running sum/range moments and the last 64 draw bitmasks.
3. Enumerate **all C(45,6) = 8,145,060 combinations**.
4. Stage A applies a fast fixed-point model and retains the best 4,096 candidates in a signed min-heap.
5. Stage B applies slower crowd, anti-pattern, recent-overlap and robustness terms and retains 512 candidates.
6. Persistence is computed as the proportion of the final candidate field containing each number.
7. `Recalculate` samples the same candidate field again rather than rebuilding the analysis.
8. An adaptive skepticism gate occasionally emits a full uniform 6/45 sample so the engine never pretends that noisy historical structure is certainty.

### Number model

For number `i`, Stage A combines:

- long-run residual `45*count(i) - 6*N`;
- short/mid/long EWMAs with Q16 fixed-point decay;
- a low-weight capped gap residual;
- Bayesian-style shrinkage behavior achieved by keeping all deviations centered on the theoretical 6/45 rate rather than treating raw frequency as probability.

The EWMA bands are implemented as fixed-point integer recurrences so the hot path needs no floating-point runtime.

### Pair graph

The expected probability that a specific pair appears in a 6/45 draw is:

`C(43,4) / C(45,6) = 1/66`.

For every pair in a candidate, ORACLE therefore uses the centered residual:

`pairResidual(i,j) = 66*observedPairCount(i,j) - N`.

This is superior to rewarding raw co-occurrence counts because it is explicitly centered on the uniform null model.

### Structural model

The parser records empirical histograms for odd-count, low-half-count and adjacency count, plus moments of draw sum and range. Candidate scoring rewards empirically common coarse structures while penalizing excessive distance from historical sum/range centers.

A five-bucket collision term acts as a cheap entropy proxy. It rewards spatial dispersion without requiring a logarithm implementation in the 8.1-million-combination hot loop.

### Deep model

Only the 4,096 Stage-A survivors pay for slower terms:

- last-64-draw overlap penalty;
- birthday-range crowd avoidance;
- round-number crowd penalty;
- repeated-last-digit penalty;
- arithmetic-pattern penalty;
- a soft clamp against one component dominating the entire score.

The crowd terms **do not increase the chance of a winning draw**. They are intended only to prefer combinations that may be less likely to be chosen by other humans if a win occurs.

### Adaptive skepticism

ORACLE measures aggregate deviation of historical number frequencies from the theoretical uniform baseline. Weak residual structure raises the skepticism percentage; stronger residual structure lowers it within hard bounds.

On each `Recalculate`, the skepticism gate chooses between:

- weighted sampling from the 512-member ORACLE field; or
- a cryptographically random uniform 6/45 combination generated by Windows `SystemFunction036` (`RtlGenRandom`).

The purpose is regularization, not an assertion that observed historical deviations are predictive.

### Persistence

`Persistence(i)` is the percentage of final 512 candidates containing number `i`. It is an internal stability measure, **not the probability that i will be drawn**.

## Planned ORACLE 0.2+ research layers

The architecture deliberately leaves room for stricter rather than merely larger models:

- walk-forward backtesting with no future leakage;
- model-level calibration against millions of uniform Monte Carlo baselines;
- bootstrap and parameter perturbation stability;
- correlation-aware ensemble weighting so related models cannot double-count the same signal;
- Benjamini–Hochberg false-discovery correction for number/pair/hypergraph exploration;
- champion/challenger algorithm versions;
- posterior model averaging with an explicit uniform model;
- rank-stability optimization instead of raw-score optimization;
- provider adapters for signed/cached historical datasets.

A model is allowed to lose weight or collapse back toward the uniform model if validation fails. Complexity is not treated as evidence of predictive power.
